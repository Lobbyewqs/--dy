# v0.4 策略与来源

## 当前策略

以动态棋盘上的短期决策为主。游戏 canStartDropTouch() 并不要求全场静止，也不要求 droppingFruitId 为 null；本版取消助手增加的全局静止门槛。仍遵守正常冷却、弹窗与 pendingDrop，合成队列短暂等待。

候选来自横向网格、目标中心、两侧和空隙，先按当前速度外推及首次接触高度筛选。最多 6 个候选进入 Planck；评价单次合成、堆高、危险线、被埋水果和接触不确定性。对前 2 个结果做左右偏移及摩擦/弹性偏差检查。远期合成奖励不累加；不搜索或读取下一水果。

物理推演用 1/120 秒步长、18/24 迭代、连续碰撞。释放时间包含普通投放横移的 min(0.22, max(0.12, abs(x-currentX)/1200)) 秒、已过去的规划时间及约 15 毫秒传输估计。目标跟踪参考当前速度；几何回退仅外推最多 0.45 秒，不模拟完整受力。

首次接触后约 0.32 秒即停止重点推演，总时长最多约 2 秒。预测包含同类合成、较低中心生成、径向推力、速度上限；仍存在接触排序和帧调度误差。仅明确 awake=false 才初始休眠，避免冻结处于瞬时零速的悬空水果。

提交前允许符合速度外推及重力容差的小幅运动，拒绝 ID/数量变化、明显偏离和超过 400 毫秒的快照；同样的检查在游戏 iframe 内执行。被拒的过期计划下一轮重算。当前模型精度不足时会回退保守几何，仍可能失败。

轨迹按时间插值，比对仍存在的水果 ID 的位置。最大位置偏差截断到 120 像素后做指数平滑；物理评分权重从 0.65 逐步降低，最低 0.15。被合成移除的水果不用于误差计算；该指标也不能衡量所有接触或长期结果的正确率。

## 已核对的游戏代码

本机保留的公开业务 assets/main/index.c3dcd.js 中，dropCurrentFruitAt、finishCurrentFruitDrop、spawnNextFruit、canStartDropTouch、preparePhysics、Fruit.applyPhysics、applyRadialExplosion 与 getFruitDebugSnapshots 提供了上述投放流程与物理参数。未复制或分发游戏业务源码，也未修改真实物理世界。

## 既有参考来源

- [ericcayers-ai/suikaAI-plus](https://github.com/ericcayers-ai/suikaAI-plus)，研究版本 `5b87e74e408811fa1fbd8872d75b9fe988a9337d`。
  - [GreedyOnePlyAgent.java](https://github.com/ericcayers-ai/suikaAI-plus/blob/5b87e74e408811fa1fbd8872d75b9fe988a9337d/suika-ai/src/main/java/dev/suika/ai/GreedyOnePlyAgent.java)：先模拟落点，再评价落子后的棋盘。
  - [BoardEval.java](https://github.com/ericcayers-ai/suikaAI-plus/blob/5b87e74e408811fa1fbd8872d75b9fe988a9337d/suika-ai/src/main/java/dev/suika/ai/BoardEval.java)：同时衡量合成收益、堆高、危险线与同级准备程度。
  - [MctsAgent.java](https://github.com/ericcayers-ai/suikaAI-plus/blob/5b87e74e408811fa1fbd8872d75b9fe988a9337d/suika-ai/src/main/java/dev/suika/ai/MctsAgent.java)：先对候选做单步估值，再继续搜索未来结果。
  - 仅借鉴上述思路，未将 Java 代码移植进交付包；本版也没有运行该项目的 MCTS。
- [piqnt/planck.js](https://github.com/piqnt/planck.js)：采用其 Box2D 系 JavaScript 物理引擎，随包提供 Planck 1.5.0 与 MIT 许可证；不在运行时从 CDN 加载。
- [Gnaij12/SuikaBot](https://github.com/Gnaij12/SuikaBot)：对照其无渲染模拟与学习方案。未采用神经网络或训练权重，也未复制其源码。

坐标单位依据 [Cocos 3.8.6 物理类型](https://github.com/cocos/cocos-engine/blob/v3.8.6/cocos/physics-2d/framework/physics-types.ts) 与 [刚体实现](https://github.com/cocos/cocos-engine/blob/v3.8.6/cocos/physics-2d/box2d-wasm/rigid-body.ts) 核对：位置按 32 像素/米转换，线速度保留米/秒，角速度保留弧度/秒。


以上项目是算法思路与物理引擎来源。v0.4 重点调整控制节奏和误差处理，已不使用 v0.3 的两步 expectimax 搜索。验证结果与限制见“验证报告.md”。
